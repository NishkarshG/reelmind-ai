# REELMIND AI — Microdrama Promo Intelligence Studio

REELMIND AI reads microdrama screenplays and finds the best **20–60 second promo moments**: strong opening hooks, emotional peaks, reveals, confrontations and cliffhangers that make sense to someone who has never seen the show. It then ranks and explains each one.

Every candidate is built from **line IDs in the original screenplay**. Timestamps and dialogue shown to editors are copied from the parsed script and never generated by the model. A Python validator checks every candidate, and candidates that fail are kept and flagged rather than silently dropped.

> Scores are **editorial promo-potential scores**. They are not predictions of views or virality.

---

## Features

| Area | What it does |
|---|---|
| **Overview** | Episode, processed and candidate counts, average quality, top episode, discovery trend chart, top-5 promos and an activity log |
| **Episode Library** | Upload ZIPs (nested folders supported) and `.txt` files with drag-and-drop and a progress bar. Search and filter episodes, inspect the parsed screenplay, raw text, continuity notes and parser warnings, and run analysis per episode or in bulk |
| **Promo Discovery** | Ranked candidates with episode, timestamps, exact hook and cliffhanger lines, an explanation and the 30/30/20/20 score breakdown. Filter by episode, score, validity and review status, sort by any dimension, and export the filtered list as **CSV / JSON** or download a ZIP of all raw outputs |
| **Review** | Editors can adjust each score with a slider, add notes, and **approve or reject** a candidate. Ranking recalculates immediately |
| **Scene Intelligence** | Interactive timeline per episode showing scene boundaries and timestamps, dialogue and action lanes, a promo-heat strip, and hook, cliffhanger and emotional-peak markers. Click any marker to read the verbatim screenplay excerpt; hover a promo to outline it on the timeline |
| **Analytics** | Score distribution, episode comparison (average, best or count), hook-vs-cliffhanger scatter, per-episode dimension bars, most common dramatic patterns and a scoring-profile radar chart |
| **Quality Evaluation** | Invalid timestamps, clips outside 20–60s, unverified excerpts, weak hooks, weak cliffhangers, potentially confusing clips, human review status, failed AI runs and parser issues |
| **Settings** | AI provider, API key status (server-side environment variable only), connection test, live model list, temperature, duration limits, multi-segment toggle, quality thresholds and export options |
| **Demo mode** | A separate SQLite database and output folder, seeded from the bundled sample scripts by the offline baseline. It is clearly labelled everywhere and never mixed with live results |

### Scoring rubric (out of 100)
- Hook strength: **30**
- Cliffhanger strength: **30**
- Emotional impact: **20**
- Standalone clarity: **20**

## Architecture

```
backend/                 FastAPI + SQLite
  app/parser.py          Screenplay parser (handles several script layouts)
  app/ai/                Pluggable providers
     base.py             AIProvider interface
     gemini.py           Google Gemini (REST, key from GEMINI_API_KEY)
     heuristic.py        Offline rule-based baseline (clearly labelled)
     prompt.py           Episode context + strict JSON prompt
  app/validation.py      Candidate validation and scoring
  app/services.py        Ingest, analysis jobs, ranking, aggregates, exports
  app/db.py              SQLite (one DB per workspace: live.db / demo.db)
  app/main.py            REST API
  sample_scripts/        5 sample episodes in 3 different layouts
  tests/                 Parser, validation and LLM-pipeline tests
frontend/                React + TypeScript + Tailwind v4 + Recharts + Lucide
samples/reelmind_sample_season.zip   Ready-made ZIP for testing uploads
```

### How analysis works
1. **Parse.** Each file is parsed into episode number, logline, continuity notes, scenes (with start and end), camera directions, and timed action and dialogue lines. Every line gets a stable ID (`L001`…). Text is preserved exactly. Missing fields produce warnings, and an episode number can be inferred from the filename.
2. **Prompt.** The model sees the screenplay as `[L012] 00:00:42 - 00:00:47 | RHEA: …` and must return strict JSON. Each candidate gives segments as line-ID ranges, a hook line, a cliffhanger line, verbatim quotes, an explanation, patterns and scores.
3. **Validate.** Python then:
   - resolves line IDs against the script
   - checks start < end
   - checks the total duration is within 20–60s (configurable)
   - checks the referenced episode exists
   - checks that quotes match the original line (otherwise flagged as *possible invented dialogue*)
   - checks segments are chronological and don't overlap
   - checks the hook is in the first segment and the cliffhanger in the last
   - checks claimed timestamps match the script, and scores are in range

   Invalid candidates are stored with their errors.
4. **Rank.** The overall score is the sum of the four dimensions, using editor overrides where present. Valid candidates rank above invalid ones.
5. **Persist.** Everything goes to SQLite, and raw machine-readable outputs are written to `backend/outputs/<workspace>/`.

If an AI call fails (bad key, network, malformed JSON), the run is marked **failed** with the error, and nothing is fabricated. The offline baseline is a separate, explicitly chosen provider, never an automatic fallback.

### Raw outputs (`backend/outputs/<workspace>/`)
`parsed_episodes.json` · `ai_analysis/episode_XXX_run_N.json` (prompt and raw model response) · `candidates.json` / `.csv` · `ranking.json` / `.csv` · `validation_errors.json` / `.csv` · `evaluation_summary.json`

You can also download them as a single ZIP from the Promo Discovery or Evaluation page.

## Installation

Requirements: **Python 3.11+** and **Node 20+**.

### 1. Backend
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # then put your key in GEMINI_API_KEY
uvicorn app.main:app --reload --port 8000
```
API docs: http://localhost:8000/docs

### 2. Frontend
```bash
cd frontend
npm install
npm run dev
```
Open http://localhost:5173. The Vite dev server proxies `/api` to port 8000.

### Single-process mode
Run `npm run build` in `frontend/`, then start uvicorn. FastAPI serves `frontend/dist` at http://localhost:8000.

### Tests
```bash
cd backend && .venv/bin/python -m pytest -q
```

## Configuration

| Variable | Where | Purpose |
|---|---|---|
| `GEMINI_API_KEY` | `backend/.env` | Gemini key. Only the server reads it; it is never stored in the DB or sent to the browser |
| `CORS_ORIGINS` | `backend/.env` | Comma-separated allowed origins (default `*`) |
| `REELMIND_DATA_DIR` / `REELMIND_OUTPUT_DIR` | env | Override the SQLite and output locations |
| `VITE_API_URL` | frontend build env | Backend URL when the frontend is hosted separately |
| `VITE_STATIC_DEMO` | frontend build env | `1` builds a read-only static preview of the demo workspace |

The model is selected in **Settings** (default `gemini-2.5-flash`). Use **Fetch available models** to list the models your key can access.

### Adding another AI provider
Create a class in `backend/app/ai/` that implements `AIProvider.generate(prompt, context, settings) -> str` and returns the same JSON contract. Then register it in `backend/app/ai/__init__.py`. Validation, ranking, the UI and exports work unchanged.

## Usage
1. Switch to the **Live** workspace (top-left).
2. **Episode Library → Upload files.** Drop a ZIP of scripts (try `samples/reelmind_sample_season.zip`) or `.txt` files.
3. Click **Analyse all**, or analyse selected episodes. Progress appears in the header.
4. Review candidates in **Promo Discovery**: adjust scores, approve or reject, and export CSV or JSON.
5. Explore **Scene Intelligence** and **Analytics**, and audit the run in **Quality Evaluation**.

### Supported screenplay layouts (mixable)
**Block layout** (one `Start/End` timing line per block, timed CAMERA and SOUND FX):
```
EPISODE NUMBER: Episode 1
EPISODE LOGLINE: ...
CONTINUITY NOTES: ...
--- SCRIPT START ---
SCENE 01
Scene heading: INT. CATHEDRAL – DAY
Scene start: 00:00.00
Scene end: 02:18.00
Actions and dialogue:
**CAMERA:**
Start: (00:00.00) | End: (00:04.80)
Symmetrical framing on the church doors...
**LADY JULIANA (V.O.) (Confused, Breathless):**
Start: (00:13.50) | End: (00:14.30)
"Why?"
**SOUND FX:**
Start: (00:20.00) | End: (00:21.00)
[Gavel strike]
--- SCRIPT END ---
```
Camera, action, dialogue and SFX blocks can overlap in time. Each promo segment spans the earliest start and latest end of its lines, and the original timestamp strings are kept. CAMERA lines act as clean cut points but are never used as hooks or cliffhangers.

**Inline layouts:**
```
EPISODE NUMBER: 1            | EPISODE 4             | Episode No. 5
EPISODE LOGLINE: ...         | LOGLINE: ...          | Logline - ...
SCENE 1: INT. X - NIGHT      | SCENE 2 - EXT. X (00:00:54 - 00:01:40) | SCENE 1 | INT. X | 00:00 --> 00:52
SCENE START: 00:00:00 | SCENE END: 00:00:52
CAMERA: ...                  | CAMERA - ...
[00:00:05 - 00:00:09] MAYA: line        | MAYA (00:00:09 - 00:00:15)     | 00:05 --> 00:11  ARJUN  line
[00:00:00 - 00:00:05] ACTION: text      |   (parenthetical)              | 00:00 --> 00:05  ACTION  text
                                        |   line text on following lines |
```

## Deployment
- **Frontend (Netlify).** `netlify.toml` builds `frontend/`. Netlify can't run Python, so by default the site is a clearly labelled **read-only static preview of the demo workspace**. Uploads, AI analysis and editing explain that the backend is required.
- **Backend.** Deploy `backend/` to any Python host. `render.yaml` is included for Render. Then set `VITE_API_URL=<your API URL>` and `VITE_STATIC_DEMO=0` in Netlify's environment variables and redeploy to get the fully working app.
- Regenerate the static snapshot with `cd backend && .venv/bin/python scripts/export_static_demo.py ../frontend/public/static-demo`.

## Notes and limitations
- The sample season ("The Silent Heiress") is original sample content written for this project.
- The offline baseline uses a keyword and structure heuristic. It is useful for demos and as a sanity baseline, but it is not an LLM.
- Re-analysing an episode replaces its previous candidates and reviews once the new run succeeds. A failed run leaves the earlier results in place.
